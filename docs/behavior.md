# Sidebar behavior

[Back to the README](../README.md) · [Installation](installation.md)

## Workflow

- **Ready:** headerless conversations ready for your attention. Pending approvals and questions remain visible here rather than disappearing into a background shelf.
- **Working:** unpinned running jobs separated from attention items and visually subdued, with a blue dashed circle and elapsed time instead of a Working label. Setting the **Working indicator** plugin setting to **Detailed** (Normal by default, saved per Desktop client) makes the circle solid while the conversation's own turn runs and keeps it dashed when only subagents or an awaited background command keep it busy; `+3` after the circle counts running subagents, so a dashed circle without a count means the session is only waiting on a background command. While the conversation compacts its context (manual `/compress` or automatic compaction), the circle becomes a pinched ring: opened on the diagonal, with two arrows pushing in; the subagent count and time stay. The card's hover title then spells this out. In that mode, when no subagent count has ever been read for the session (for example when the runtime cannot project subagents), the circle is omitted and only the elapsed time shows. Desktop's blue token is #0053fd in every theme, too dark on dark backgrounds, so the plugin mixes it with the theme's text color: lighter in dark themes, deeper in light ones. Running subagents also give an idle parent Working status; waiting for user input still takes priority.
- **Snoozed:** conversations put aside until a chosen time: +1h, +2h or +4h from now, Tomorrow, Monday or Next week, or a custom date/time. The three day choices share the **Snooze preset time** in the plugin settings, defaulting to 09:00 in the Desktop client's local time. The preference persists locally and applies to new snoozes only. On a Monday, Monday means the following Monday; on a Sunday it is the Monday after tomorrow, so it never repeats Tomorrow. Next week is the same weekday seven days later. Calendar arithmetic preserves the configured local time across daylight-saving changes.
- **Archived:** Hermes’s real archived sessions, including conversations archived outside this plugin. Archive and Unarchive use native session archival; history is retained. The shelf is ordered by last activity, not an invented archival timestamp.
- Headerless Pinned cards above Ready, two-line session cards, search, project filtering and hover-only Snooze/Archive actions. Pinned sessions stay here while working, retaining blue Working status without dimming; Snoozed still wins over Pinned, while native archives and input/unknown-status safeguards keep their existing precedence. Pinned fits its cards without reserving blank space; large pinned lists remain height-capped and scroll independently. Category bodies scroll independently while secondary headers remain visible.
- Pinned cards form one group: a 1px outline running exactly along the cards' backgrounds, under the cards (a hovered or selected card covers its part, and cards keep the width of Ready cards), with a single accent pin on its top border instead of a pin on each card. A pinned card shown in another shelf, such as Snoozed, keeps its own pin. The group adds 6px above the cards for the pin and 5px below them, and disappears entirely when no pinned session matches the current search or project filter.
- **Pinned sessions**, 2 lines by default in the plugin settings, sets the height of pinned cards. **1 line** drops the project name and provider and puts the title between the project icon and the token count and status, for 33px cards instead of 56px with the default geometry; other shelves keep two lines. It applies immediately and persists per Desktop client.
- **Show token counts**, on by default in the plugin settings, controls the total input/output token counter on every session card. Changes apply immediately and persist per Desktop client across sources and profiles. Turning it off removes only the counter, including its unavailable-value placeholder; provider icons, status indicators and times remain visible.
- **Done/Input sound**, None by default in the plugin settings, plays the chosen sound when a card shows **Done** or **Input**, read from the same card status as the badges: Input for a question or approval, Done for a backend completion marker (or native unread) that no Working status outranks. It plays for a new question, and for a completion the card has not shown before: a card leaving Done for a turn that records no completion (a `/loop` wake-up) and coming back to the same marker stays silent. The open session counts too, although its Done badge is hidden while it is read. The first snapshot, older history loaded later and a failed poll's leftover statuses set the baseline without a sound. Done itself waits for work a turn leaves behind: the backend records no marker for a turn that ends while a notifying background process will still report back, or while a child result it has not delivered yet will wake the conversation (see [completion markers](completion-markers.md)), so the turn that receives that result gives the sound. Desktop's own Completion Sound plays at every turn end. Plugins can neither add a sound to it, hold its cue back nor change it: `host.settings` does not expose it, and its store does not follow outside writes until a reload. The picker repeats Desktop's own, with Preview beside it: None, T3 Code's sound (marked with a star only; the Select's own styling marks the active choice) and Desktop's 14 presets under their Desktop names, ported from its `completion-sound.ts` so they sound the same; choosing one or Preview plays it, and the choice persists per Desktop client. A line under the row, across its full width, reads Desktop's own setting from the keys its stores persist (read only, never written). On the left it says whether Desktop's sound also plays, in orange while it does ("Desktop sound is not None (Two-note comfort): both will play at the same time. Set it to None."), in green once it is None or interface sounds are muted, neutral when the value cannot be read. With this sound on None the line stays neutral grey and says what plays instead ("Only Desktop’s own Completion Sound plays (Two-note comfort).", or that none does). On the right, **Go to setting →** opens Desktop's Completion Sound row. The row's description gives its reason: Desktop's Completion Sound plays at every turn end, including when the agent hands work to subagents or waits for a background command while the session is still Working. The line rereads the setting on return, on window focus and on cross-window storage events. Desktop's **Mute interface sounds** also silences this automatic sound, as it does Desktop's; Preview still plays. It relies on the sidebar's polls, so it needs the sidebar open.
- Working, Snoozed and Archived cards dim only their titles, which return to full contrast on hover, focus or an open menu. Status labels, colored icons and metadata stay readable; hover actions replace the metadata instantly.
- Cards show a monochrome mark for every Hermes provider that has one: 34 marks from LobeHub Icons 1.95.1 (MIT, see `THIRD_PARTY_NOTICES.md`), mapped from Hermes provider ids and their registry aliases. Actual Computer, GMI Cloud, Ramp Router and Solstice have no published mark and show none. The mark and token count share a quiet color (30% of the text color), the denser mark at 0.7 opacity.
- Card geometry is themeable through three CSS variables, settable on `:root` or any ancestor: `--sf-card-content` (default 42px, the two text lines; one-line pinned cards use 19px), `--sf-card-padding` (6px) and `--sf-card-margin` (1px), both vertical and per side. The margin is a transparent border, so adjacent hovered, selected or draft cards keep a visible gap (2px by default). The row stride, 56px by default, drives windowed scrolling and the shelf minimums; lists read it when they mount.
- Shelf heights are pure CSS (flex), as a share of the area below Pinned. Ready first gets its cards up to 40%. Working, Snoozed and Archived each keep up to two whole cards (at most 20% in short panes) and never reserve blank space below fewer cards. Whatever the share, an open shelf holding a card, Ready included, never drops below its heading and one whole card, so a title is never cut down to its metadata line. In short panes Ready's 40% gives way first to the other shelves' floors; only when the floors alone add up to more than the pane holds do the shelves scroll together instead of clipping the lowest ones. Remaining space is split equally, so categories that all overflow end up the same height. Working and Snoozed can grow to show all their cards; Archived stops at 40%. Space nobody needs stays blank under Ready, keeping the headings at the bottom. A JavaScript allocator with exact priorities (Ready-first even in short panes, Working/Snoozed capped at 40%) was built and profiled as an alternative; flex costs about the same and was kept for its simplicity, with approximate priorities in very short panes.
- Every category puts the most recent first: Working by when its turn started (shortest working time on top), so cards no longer reorder on every message, using last activity when the start is unknown; Snoozed by the nearest wake time; Ready, Pinned and Archived by last activity.
- Opening an old session rebuilds its agent, which Hermes reports as `starting`. That alone is not work: the card stays where it was, without a Working badge, and Archive/Delete/Move stay refused until the build settles. A prompt sent during the build (an in-flight turn with its start time) shows Working immediately.
- A session counts as Working while a background process it started is still running and will report back into it (`notify_on_complete` or watch patterns), or its completion notice is still on its way, using Hermes's own predicate. Background servers that never report back do not count. Authority-mode runtimes do not expose process ownership, so there it stays unknown and never implies Working.
- Context compression is transparent to the Working time. Compression inside a turn keeps the turn's native start; a manual `/compress` runs without a turn or plugin hook, so the backend times it from when it first sees the compaction (the runtime refresh is triggered by its status event). That start lasts until the compaction ends, survives across polls and is forgotten when the runtime disappears.
- The first load shows three skeleton cards with the real card geometry and a subtle shimmer (static under reduced motion); screen readers hear “Loading sessions…”. Loading archives inside Archived stays a line of text.
- Problems share one single-line strip above the list instead of a box each: an icon, a short summary of the most important one (an action's error first, then a failed session list, an unavailable backend, unknown runtime status, older history that could not load, then neutral states such as checking runtime status or the read-only SDK listing), `+N` for the others, **Retry** when a feed can be read again, and a disclosure with every complete message. Errors are announced as alerts, neutral states as status. While the strip reports the whole list's runtime status as unknown, cards drop their visible `?` (each still says “status unknown” to screen readers); the `?` stays when only some cards are unknown. The strip never shows without a problem, and the status-dependent safeguards are unchanged.
- The footer's **Usage** and **Limits** buttons toggle their page: clicking the button of the page shown closes it and reopens what the workspace showed before any page opened, the last session or the new-session draft, so Usage → Limits → Limits returns to that session rather than to Usage. A session that no longer lists, or fails to open, falls back to a new chat. The shown page's button is marked as the current page and named “Close Usage” or “Close Limits”, in its tooltip too.
- Tooltips are Desktop's own (the SDK Tip), never alongside a native title; hosts without it keep native titles. Cards and their menus share a single tooltip rather than one per element: a card's title in bold, its folder dimmed, then its branch and status after a longer hover (or at once on keyboard focus), to the right outside the pane, and the hover actions' names past the card's right edge, so neither neighbouring cards nor the other action are covered. Toolbar tips open below the toolbar, footer and page tips above their control.
- Cards animate in and out (220 ms) whenever they appear or disappear: search, project filtering, or moving between categories. The card keeps its full height while its enclosing slot clips it; a leaving card is an inert, aria-hidden clone without session IDs, so it can't be focused or acted on. Categories that fit their cards grow and shrink with them; card motion may resize a category's scrolling list (only folds keep lists at a fixed size). The first load, windowed lists (over 80 cards) and reduced motion change instantly. An empty Pinned stays mounted at zero height so its last card can animate out.
- A scrolling list's bottom edge fades out while more cards lie below it, so content never runs hard into the next heading; the fade disappears at the end of the list. Folding and unfolding move only a category's edge: every shelf list keeps its size for the duration (the larger of its start and end heights), slides under a fade at that moving edge, and then releases. Lists never resize or toggle scrollbars mid-animation.
- Working, Snoozed and Archived headings are 30px tall, with 6px of extra space above, and show a medium-weight label in the theme accent color, a plain session count, a divider and a right-aligned chevron. A heading whose count is 0 shows its label in a quiet neutral color instead, so empty shelves recede. Fold preferences persist locally through Desktop restarts, separately for each source and profile. Searching temporarily reveals matching Working rows, but never automatically unfolds Snoozed or Archived; their matching counts remain available for explicit expansion.
- Project glyphs have transparent backgrounds in both cards and the new-session picker. The picker closes through the normal popover dismissal without a Cancel button. Searches with no loaded matches show “No matching sessions”, never “All caught up”, directly under the search field (cleared with its cross). When older history can still be loaded, the message adds that search covers loaded sessions only and offers **Browse older sessions**.
- Keyboard: the focused card shows an accent ring along its rounded background (keyboard focus only, not after a click). ↑/↓ or Home/End focus cards, Enter opens, Shift+F10 or the context-menu key opens actions, and Shift+Enter archives a confirmed-idle card and opens the next Ready or Pinned session, or a new draft when none remains (on an archived card it unarchives instead).
- Reverse actions through ordinary controls: Archive/Unarchive, Pin/Unpin and Unsnooze in the Snooze menu. No action creates an Undo toast or button; Delete retains its confirmation modal.
- Menu buttons stay highlighted until their popover closes, and show no tooltip while their menu is open (it would cover the menu and take its first Escape). Snooze also keeps its hover controls visible and its anchor stable when the pointer leaves the card. The session, Project and Snooze menus stay open after an action and show its result in place: Pin becomes Unpin, a snooze adds its wake line with **Unsnooze**, a rename shows the new name. A card that moves (pinned, snoozed, unsnoozed, reordered, started working) takes its open menu along, scrolled into view: the menu glides from where it was to its new place in about 0.3 s instead of jumping, and goes straight there under reduced motion. Only a move into a folded shelf, where the card is hidden, closes it: the menu fades out where it was, without moving. Delete still hands over to its confirmation dialog. The sidebar's menus and pickers fade in in 150 ms while sliding 6px out of the side they open from (from the left for the card and project menus, from above for Filter and New session), and fade out in 150 ms without moving; a menu that follows its moving card does not fade in again. Reduced motion keeps the fades without the slide.
- Provider icons appear only when concrete metadata identifies a supported logo. Missing, automatic or unrecognized providers have no placeholder icon or empty spacer; the logo appears when metadata arrives. When stored provider metadata is missing, the exact session tip's unambiguous runtime provider fills the gap, including after the first prompt while tokens are still zero. Known stored providers are preserved; ancestor and internal runtimes cannot supply the fallback.
- The focused search field shows a background and inset accent ring across its full width. Search retains keyboard focus as filtering removes cards. Row-focus recovery only applies while the card actually owns focus; background list updates do not reclaim focus from search, menus or the composer.
- The pane tab is named **t3sidebar**; the plugin ID and storage namespace remain `hermes-t3sidebar`.
- Cards show green **Done** for a backend-recorded successful completion, or native backend unread when available. Completion markers persist in profile-scoped plugin SQLite even with Desktop closed; clients read the same state and acknowledge its exact generation when a thread is opened/read. No client-local completion tracker or native unread rewrite is used. See [backend completion markers](completion-markers.md).
- Purple **Woke** after snooze expiry and orange **Input** for a question or approval retain priority over Done; blue Working also outranks Done. Done, Input and Woke use T3 Code's check circle, question bubble and alarm clock, bundled with the plugin rather than taken from the Desktop SDK. Each has a bold title. Working shows T3's still dashed circle and the elapsed time (`12s`, `4m`, `1h 5m`) instead of a visible label; screen readers still hear Working. The time updates every second and counts from Hermes's own in-flight turn start, which arrives with the same runtime refresh that reveals Working. A parent kept Working only by subagents counts from its last turn's start, recorded by the backend hook. Without any recorded start, the dashed circle shows alone.
- Snooze uses purple alarm icons: an alarm on the hover button, alarm-snooze before a snoozed card's remaining time and at the start of the Snooze menu's wake line, and a green alarm-off on Unsnooze. Project names, glyphs and ordinary ages have stronger contrast while provider/token metadata stays subdued.
- Categories animate open/closed without moving their headers into the scroll bodies; reduced-motion preferences disable these transitions.
- The right-click session menu is 520px wide. Its first line is the title with **Rename** and **Rename with AutoTitler** icon buttons at its end; the second is the session ID in small grey monospace with **Copy**, which answers with a green check mark for a moment and keeps the menu open. A session with an unsent draft gets a third line: an orange pencil, the start of the draft on one line fading out at the edge, and a red **Discard draft** cross. The draft text is read from the composer, or from the synced draft store, when the menu opens, and is kept in that menu's own state, never in the query cache. Under a divider, an icon-only toolbar shares the width: **Pin/Unpin**, **Delete session**, **Move to project**, a vertical divider, then **Project**. Every icon-only button names itself in its tooltip; a disabled one adds why (Delete and Move wait for an idle session). The **Project** menu, also 520px wide, starts with the project's icon and name with **Rename project**, then one line per project folder: **Filter** in the icon column, the path, and **Copy path**. While that folder filters the session list, its **Filter** is a cross, **Clear filter**, whenever the menu is open; clicking the current color or icon resets it, like **No color** and **Default icon**. Under a divider, a tall **No color** button sits left of the approved 48-color palette (24 hue-aligned bright/dark pairs in golden-ratio portrait swatches), and a tall **Default icon** button left of the 64 native Codicons, grouped by name in four columns of eight-icon categories. All selectable project glyphs use the chosen project color; action icons keep their ordinary styling. Right-click a project in the filter list (or use Shift+F10) to open the same menu without selecting that filter or changing workspace. Project edits update the native backend catalog and verify exact saved values; auto-discovered folders are adopted as native projects on their first edit, without changing the active workspace. Delete's icon uses the native red theme color, including hover/focus and disabled states. Session Rename verifies the saved title. A session with a live runtime is renamed through Hermes's `session.title` RPC, provided it is still the same runtime; stored history without one (typically archived or older threads) is renamed through Hermes's authenticated HTTP rename, as the native sidebar does, and the stored title is read back. Rename is disabled for an unsaved card that has neither stored history nor a live runtime, such as a synced draft. Archive and Snooze stay on their direct hover controls, and archived cards omit Snooze. Lists are always flat; project filtering does not group them.
- The Snooze menu leads each row with its icon outside the buttons, in one column: a clock before **+1h**, **+2h** and **+4h**; a calendar with the preset time written under it before **Tomorrow**, **Monday** and **Next week**, each with its short weekday and date on a second line and the full wake date in its tooltip; and a calendar-with-clock before the custom field. An existing snooze adds one purple line above them: its wake date and time, the precise time left, and **Unsnooze** at the end.
- Custom snooze uses the date/time field with Enter or its adjacent checkmark; there is no bottom “Snooze until chosen time” button. The custom row has no text label, and the field starts where the buttons above do. The checkmark is a filled button with a bold mark, turning green once the field holds a valid future local time; an invalid value can still be submitted to see what is wrong.
- Opening a thread marks it read but does not change its displayed conversation age or recency order. Stored conversation activity, not the runtime's resume/reattach clock, drives those values.
- Token totals have whole-thousand resolution (`12K`, not `12.3K`) and one decimal for millions (`1.2M`). Archived cards never show Done, Woke, pin or snooze indicators/actions. Viewing their history leaves them archived; resumed agent activity restores their native compression lineage through the backend plugin hook. Authoritative running/input state leaves the Archived shelf immediately, even before the persisted flag refreshes.
- **Move to project**, just before the divider and **Project** in the session menu's toolbar, re-homes a confirmed-idle stored conversation to a selected project folder through the native workspace-move operation. Folder choices include multi-folder projects. The companion verifies the exact persisted workspace before the card changes; moving never opens the session or sends a prompt.
- Working fits its cards through intrinsic CSS sizing rather than calculated JavaScript heights; large Working lists still scroll within the pane's height limit. Session cards keep a 3px gap between their two text lines without changing the 56px card height. Search keeps an explicit clear cross visible whenever the input has text. Rename uses a checkmark beside its field, and Input/Working/Done labels are bold.
- A draft gives its card a dim orange background only while that session is unfocused: nonempty text in this Desktop's composer, or a draft saved on the server from any client. The focused editor retains its ordinary selected background. A small orange pencil at the far right of the metadata line, after the time and any Input, Done or Woke badge, marks every card with a draft, the viewed one included: there it follows the composer's own two-second read, appearing as text is typed and leaving once the composer is emptied or the message sent. The hover actions cover it with the rest of that side, and the card's tooltip and accessible description then name the “Unsent draft”. Per-card composer reads keep only a boolean; folded bodies do not poll.
- Empty, untitled sessions stay out of the list unless they hold a draft. Those draft cards display **New session**, with the exact runtime workspace's project name, icon/color and concrete provider metadata even before the first message. The first real message makes it ordinary history.
- Drafts are synced through the plugin's own store (`session_drafts` in `state.sqlite3`), for every session, including follow-ups in existing conversations, with one `POST /drafts/sync` every 30 s per Desktop, both ways: its unsent changes go up, and only the drafts changed since its cursor (a sequence the server increments on every write) come back. The focused composer is also compared locally every 2 s, without a request, so its card follows typing; a change waits in plugin storage until the server confirms it, so text left in a session survives Desktop's prune and a closed window. The most recent edit wins: the server dates each edit by its reported age (the client's clock at sending minus at the edit), capped to one 30 s slot and subtracted from its own receive time, so clock skew between machines does not matter. A newer edit from another client replaces a composer still holding the text it last synced; a local change is uploaded. Blank text, a sent message (even one sent just before switching to another session, which the session's last read on leaving sees) or **Discard draft** deletes the draft, kept on the server as a marker for 30 days so other clients clear it too. Desktop's dead-session prune erases the local text of a session without stored history a few seconds after leaving it; on return, an empty composer under an existing draft gets the synced text back, and a session not yet reconciled is never read as a deletion. A draft whose session has neither stored history nor a live runtime on this server shows as its own card; opening it starts a new session in the draft's folder, puts the text in and moves the draft onto it (a draft without a folder goes into a fresh Home chat and leaves the server). Only text is synced: the public composer API does not expose attachments. Plugin storage keeps the cursor, the synced drafts and unsent changes; queries keep only which sessions have a draft, never its text.
- The new-session picker lists supported project folders, without the unsupported Home entry or its explanatory text. The filter button opens project choices directly; while filtered, it shows the selected project's icon instead of the generic filter icon.
- Filter and New session share the same native project list, always-visible name/path search and right-click/Shift+F10 project menu. Only Filter includes **All projects**. Paths are dimmed and shorten the owning backend user's home to `~` without changing the actual selection/copy/create paths. A multi-folder project appears once as a non-selectable heading with selectable folders indented below; searching for one folder retains that heading. Its heading's menu still edits the project, and lists every folder with its own Filter and Copy path.
- Project pickers use compact 24px menu rows, with a single-folder project's dimmed path on the right and grouped folder paths tightly indented below their heading. **All projects** shares the project icon/label column. The active filter choice is marked by a row background rather than a trailing check. The picker can grow to 720px when space permits, respects the viewport/native popover height, and scrolls its choices independently of the contained search field.
- Right-click **Delete session** keeps Hermes's destructive confirmation modal. Deletion is revision/generation-fenced and verified against exact stored IDs; Cancel does nothing, errors remain visible, and ambiguous retries reuse the original request. Busy sessions are not interrupted automatically. Permanently retired session IDs are excluded from runtime listings even if an old chat remains mounted; missing history alone does not imply deletion. Genuine unsaved runtime-only drafts have no stored history to delete; once a draft is persisted its card can be deleted like any other session.

Archive/Unarchive calls Hermes’s profile-routed `session.archive` operation with an explicit boolean and verifies the exact stored session’s flag through the read-only companion before confirming success. Archival applies to the native compression lineage; it is not deletion, an agent-stop operation or a hidden prompt. Pins and snoozing remain plugin-owned organization metadata. Snooze eligibility is based on an absolute server timestamp: closing Desktop does not reset the deadline. Due items become Ready on the next metadata refresh; no background agent is resumed.

Earlier versions used a plugin-only settlement shelf. Existing settlement metadata is retained for compatibility but does not count as native archival and is not automatically converted by bulk-writing session history. Those conversations rejoin the ordinary list unless another current condition (such as a pin, snooze or running job) places them elsewhere. Archive them explicitly to move them into Hermes’s real archive.

## Limitations and compatibility

- Works in the selected gateway/profile scope, rather than silently aggregating different accounts or servers.
- The server companion provides persistent pins, snooze, profile-qualified runtime status, native archive-state readback and separate rich history/archive pagination. If unavailable, the SDK’s first 500 regular rich sessions remain browseable with an explicit cap; organization and native archive actions are unavailable, with no local metadata or unqualified runtime fallback. An archive-list failure is reported rather than presented as an empty archive. A failed poll after an earlier success keeps the last successful runtime/archive snapshot, so cards stay on their Working/Snoozed/Pinned/Archived shelves; the failure is still reported, and statuses show unknown so archive, delete and move wait for the next successful refresh. Polls that overlap the plugin's own write are discarded and retried rather than reported as failures.
- Older regular history and archives load on demand independently. Organized regular sessions are recovered outside the recent page automatically, including due snoozes. Search covers loaded rows and recovered organized sessions, not history that has not yet been loaded.
- Native archived-and-hidden conversations can appear in Archived, but Unarchive deliberately preserves their separate hidden flag. They will not return to this ordinary session list unless their native visibility is changed separately.
- Pins are hermes-t3sidebar metadata, not synchronized with Hermes’s native pin store. Drag/reorder, bulk selection and cross-profile aggregation are not implemented in this version.
- Snooze is plugin-owned metadata and remains available while a stored session is working; it never stops or resumes execution. Snoozed cards show a purple alarm-snooze icon (16px, as large as the Working circle) before the non-bold remaining duration, rounded to one whole unit (for example, 2d 16h becomes 3d), without a “left” suffix. A snoozed session that is still working stays on the Snoozed shelf but also shows the blue Working icon and elapsed time, between the token count and the countdown. Their menu starts with one disabled blue information row: the wake date/time on the left (client-local short date and time separated by a space, without a comma) and precise `Xd Xh Xmin left` aligned to the right, without leading zero units (`12h 14min left`, `5min left`). Green Unsnooze is the first enabled action and is not duplicated in the right-click menu. Native Archive still requires confirmed idle status, and input/unknown-runtime visibility takes precedence over snoozed placement.
- Runtime Working/Waiting state comes from the gateway’s live session snapshot, not its connection status or a recent-activity heuristic. Unknown runtime status must not be presented as confirmed idle.
- Activity-based unarchiving is a best-effort `pre_llm_call` hook, not a session-open side effect. It restores the compression lineage through Hermes's public archive setter, which leaves independent forks archived, as Desktop's own Unarchive does. Native archival has no atomic lineage compare-and-set, so concurrent external archival/lineage changes remain a core API limitation.
- Done now uses shared plugin-owned backend completion markers, with native backend unread as an additional signal. This is not an exact projection of Desktop's private green-dot store and does not retroactively mark old idle history. The producer requires supported server lifecycle hooks; the inspected opt-in `codex_app_server` runtime bypasses its end hook and is not covered. The `openai-codex` provider alone does not imply that runtime. No core patch, native unread rewrite or timestamp-based completion guess is used.
- Delete delegates through the companion to the native authenticated HTTP deletion endpoint, avoiding `session.mutate` on Desktop's legacy RPC transport. Core retains revision/generation fences, durable request receipts, busy/lease guards, lineage deletion and transcript/request-dump cleanup; the companion and client verify exact stored-ID absence. The plugin does not perform the native Desktop's private tab/journal/cache cleanup. Deleting the currently focused session opens a fresh draft through the public SDK after verification. Hosted plugin processes without native actor context fail unavailable instead of bypassing native authorization or falling back to legacy deletion.
- Project filtering does not change Hermes’s sidebar grouping or the draft workspace.
- **New session** opens a project picker. A named project creates the session through Hermes's `session.create` in that project's folder, opens it, then sets and verifies its workspace with `session.cwd.set`; if the selection changed after creation, that update is not sent and an error says so. Home is not offered: the public SDK cannot select a detached workspace. A list filter never chooses the new chat’s project.
- T3-specific provider, worktree, PR and terminal orchestration are not recreated. This is a session-navigation plugin, not a replacement for Hermes’s workspace or T3 Code itself.
